# 实施路线图

目标是可嵌入的 Node.js 依赖包，独立启动方式作为 Demo。鉴权网关、用户系统、部署平台不在本仓库的产品范围内；包需要提供清晰的宿主接入边界和可验证的资源生命周期。

历史基线为 0.8.4（ca5ebe4）；0.9.0 统一元素路径并增加真实业务回归；0.10.0 增加短时断线恢复。原演示验证及前后对照不等于真实业务验收。

## 当前：依赖包入口与 Demo 分离（0.11.0）

- [x] 公共入口 `createMirror(options)`，引入包不监听、不启动浏览器、不注册进程信号。
- [x] 显式 HTTP/WS 接入和幂等异步关闭；实例状态独立，关闭不结束宿主服务。
- [x] 原启动方式迁入 Demo，保留 npm/Docker 体验入口。
- [x] 提供类型声明、最小宿主与迁移说明，增加导入副作用、多实例和生命周期测试。
- [x] tarball 安装到独立宿主后验证入口、静态资源、WS 拒绝与关闭边界，并加入 CI。

当前边界：这一步只完成库的组织与基本契约，不代表浏览器业务回归、npm 发布、用户身份绑定或生产加固已完成。浏览器回归已切换 Demo 入口，须对新版本执行后才能沿用验收结论。

## 下一步：宿主集成契约

数据下发边界已完成首轮[本地合成验收](acceptance/data-boundary-2026-10-26.md)：默认剔除隐藏 input 值，并提供显式属性名剔除配置；隐藏文本、CSS、资源正文和像素仍不提供自动敏感数据识别。这一步不能替代身份、网络访问或 sanitizer 的安全验证。

1. 已提供可选宿主身份回调及恢复归属绑定，见[身份边界验收](acceptance/session-identity-2026-10-26.md)。继续完善宿主注销/权限变化后的连接撤销接入；不在包中建设用户系统。
2. 固定事件、错误、配置与版本兼容规则，补真实宿主使用打包产物的浏览器业务和恢复验收。
3. 明确允许的导航、资源和字段下发边界，提供可被宿主配置的策略；说明 Chromium sandbox 和网络隔离的运行要求。
4. 按实例测试容量、长稳、故障回收与多实例资源影响；产出宿主资源预算和限制建议。

依赖包生产准入要求：宿主能安装固定版本、明确处理失败、正确释放资源，并在约定业务与资源范围内通过验收。Demo 成功、编译通过或 npm tarball 可安装都不能单独替代该准入。

## 已有验证与后续保留范围

## 1. 固化回归基线

- [x] 修复 DOM 模式滚动后首次点击丢失，覆盖页面与内层容器。
- [x] 提供真实鼠标一次点击回归脚本与专用 fixture。
- [x] 将隔离 Docker 浏览器回归接入 CI，并在失败时保存证据。
- [x] 当前构建及同一 CI 命令本地复验通过。

发布检查：提交推送后确认远端 CI；本地通过不等于远端已通过。

完成标准：可见、页面滚动、内层滚动三项均以首次真实点击触发服务端业务计数；失败返回非零；记录 WS 与日志；测试结束无遗留容器或网络。

## 2. 一个真实业务系统

首个候选为 Vikunja，使用新建本地隔离实例、SQLite 和合成账号/任务，不接入已有业务或真实凭据。具体镜像版本/digest 在实验记录中冻结。

三条流程：登录；创建任务；修改优先级为 Medium 并标记完成。先跑直连基线，再分别验证 DOM 与 frame。

首轮三通道核心流程及 API/UI 双重断言已通过，见 [验收记录](acceptance/vikunja-2026-10-26.md)。短时断连、同账号会话隔离及过期重建也已通过，见 [恢复验收](acceptance/recovery-2026-10-26.md)。退出登录、真实网络黑洞、长稳和容量仍待后续覆盖。

验收要求：

- 以真实 UI 操作创建或修改业务状态，另用应用 API 或数据库读取确认持久化；只看到文本或 HTTP 200 不算完成。
- 每通道使用独立浏览器上下文和可区分的合成记录，避免复用登录态或把直连结果算作镜像成功。
- 记录 URL、版本、视口/DPR、步骤、截图、服务端事件及结果；不得保存登录密码或会话 token。
- 区分应用自身故障、自动化选择器错误、镜像兼容问题和资源不足。
- 核心流程通过后，再补断连、退出和会话隔离。未通过时保留阻塞步骤，不扩大目标数。

## 3. 收紧依赖包交付边界

在已选真实流程上完善宿主身份接入、源站/导航/资源策略、字段下发策略和浏览器隔离要求。入口鉴权、TLS 与 WS 来源控制由宿主实现；包提供必要接口和约束。先定义允许行为与字段，再实施限制并回归核心流程。

完成标准：允许和拒绝的访问路径均有可重复测试；明确哪些数据仍下发；关闭未使用能力；不承诺字体混淆保密或 frame 纯像素隔离。

## 4. 容量与稳定性

已完成 0.10.0 的[单会话性能调查](performance/2026-10-26.md)：记录 DOM/frame 分段耗时、Rust/Wasm 扫描内核及合并窗/CPU 配额对照。后续[绘制与解码复用对照](performance/2026-10-26-codec-and-presentation.md)也已完成，尚未证明当前业务端到端加速；容量验收仍未完成，进一步的[关联帧续测](performance/2026-10-26-frame-trace.md)已定位主要等待位于源站 UI/渲染/捕获段；4ms 轮询未证明端到端稳定改善，下一步再细分该上游区间。

固定应用数据、操作序列和主机资源，测量 1/3/逐级增加的会话负载，记录冷启动、交互延迟分位数、消息流量、CPU/内存及断连回收。最后进行持续运行和故障恢复测试。

完成标准：给出可重复的实例容量、资源预算、并发拒绝/降级条件和升级兼容说明；部署与回滚由宿主负责。此前的 5 秒演示采样只作参考，不作为容量保证。

0.10.1 已将 RGBA 裁剪复用正式接入 frame，正确性、业务与恢复回归通过，见 [正式优化验收](acceptance/frame-codec-0.10.1.md)。单块编码开销降低，未证明端到端稳定提速。

## 范围控制

保持 dom + frame，优先完成依赖包契约与真实宿主流程；不建设完整产品、不增加新通道、不重写语言、不提前构建浏览器集群。每阶段通过验收才扩大范围。
