# RBI · DL 引擎线排期（strict 通道）

> 两个不同的引擎，分开做。本线是 **strict 旁路通道**：显示列表（Display List）指令流，
> 服务端保真 100%、语义零泄露。不做默认模式，不替代 DOM 线（见 `docs/roadmap-dom.md`）。

## 定位

- 目标档位双选：**strict**（纯画布，零语义泄露，输入类原生手感让渡，按 RTT 计）；
  **accessible**（画布 + 字形覆盖层恢复选字/读屏，泄露面=DOM 级）。部署时按客户选档。
- 服务场景：文字不能出沙箱的页面、需要无限放大取证的审查场景、保真度参照系（100% 黄金对照）。
- 措辞纪律：cc:: 是浏览器合成器，不是 OS 内核；对外表述统一"浏览器合成器级"。

## 与 DOM 线的关系

- 不共默认通道、不共享内核分叉负担：补丁版 Chromium 仅在 strict 通道启用。
- 安全更新策略：跟上游 stable，CI 重放补丁；不把默认流量放在分叉内核上。
- 论文/专利：先做现有技术检索（合成器帧转发、远程显示列表、分进程渲染均有公开工作），
  novelty 限定在"补丁版 Chromium 的 SkPicture 流式化用于浏览器隔离"的工程组合与实测。

## 仓库资产（本分支已含）

- `patch/chromium_paintop_export.patch`：Finalize() 导出补丁（v2 版由源树现场生成，POSIX 原生 IO）
- `lib/skp-stream.js` / `lib/skp-watcher.js`：服务端采集（CDP 通道 + dump 目录通道）
- `client/skp-replay.js`：客户端 CanvasKit 重放
- B 路线 v8 全量（displaylist.js 采集器 / server.js DL 会话 / client 画布与交互）作为对照与事件层来源
