# 宿主身份与会话恢复验收（2026-10-26）

本轮只验证本地合成宿主的 WS 入场及恢复归属，**不证明能够普遍防御渗透测试**。新增可选 `getSessionIdentity(req)`：宿主先验证凭据，包将得到的稳定身份纳入恢复 scope。未配置时仍为匿名模式，Demo 不自动获得鉴权。

## 威胁模型与前后对照

前提是测试者持有一个真实、尚未过期且已断线的恢复 token；不是猜出 256-bit 随机凭据，也不是无条件取得任意会话。攻击身份使用有效但属于另一用户或租户的独立凭据，复用相同的源站和请求 Origin，并在头及 hello 中伪报原用户。

合成宿主用随机生成的测试凭据表验证身份，登录引导也需要表中的有效凭据。HTTP 路径另作鉴权，WS 身份由服务端字段提供。凭据和恢复 token 只在进程/测试浏览器内存中使用，不写报告。它是一个封闭验证夹具，不是可直接用于生产的登录实现。

先要求另一用户能正常创建自己的独立 Chromium 会话，确认负对照不是“所有请求都被拒绝”。原用户真实输入草稿、点击提交，由独立源站事件确认仅提交一次，再关闭客户端页面。分别使用 DOM、frame 运行以下步骤：

| 检查 | 未绑定身份的旧引擎 | 新引擎，配置身份回调 |
|---|---|---|
| 另一有效用户使用已知 token | 可恢复并取得原草稿 | `SESSION_EXPIRED`，未恢复 |
| 同名用户、另一租户使用已知 token | 可恢复并取得原草稿 | `SESSION_EXPIRED`，未恢复 |
| 原用户恢复 | 原 Chromium 与草稿保留 | 原 Chromium 与草稿保留 |
| 自动重放提交 | 0 次 | 0 次 |
| 已撤销身份，重新升级 WS | 仍可使用 token | HTTP 401 |
| 无有效身份，使用已知 token | 仍可使用 token | HTTP 401 |
| 撤销前已经建立的连接 | 仍响应 ping | 仍响应 ping：须由宿主主动关闭 |

旧引擎没有这个身份回调，忽略该新配置；旧宿主本可另外实施 WS 入场鉴权。因此，“未认证仍可连接”的基线不能解释为绕过了某个已正确配置的旧版鉴权提供方。核心归属对照是：另一位有效用户即便通过入场鉴权，也不应借已知 token 恢复原用户会话；新增 scope 绑定解决了这个条件下的接管。

## 实现边界

- 身份回调同步执行，返回非空字符串；空值、异常、非字符串或 Promise 均拒绝升级，不创建浏览器。异步鉴权应由宿主先完成。
- 身份来源是宿主确认的请求上下文，不能直接采信用户名头、query 或 hello。包不解析登录密码或自建用户系统。
- scope 绑定源站、请求 Origin 与身份；推荐键包含租户和用户，必要时加入登录会话版本。错误身份与未知 token 均返回会话过期，不回显原所有者。
- 回调只保护 WS 入场及恢复，不保护 HTTP 资源、持续重验连接、源站业务权限或来源站点本身。
- 撤销账号后，已打开连接仍能响应 ping，本轮明确观察到了这一点。宿主注销、禁用或权限改变时必须主动关闭对应连接；不能把新升级 401 宣传成已有会话已撤销。
- 新钩子不提供速率限制、完整 Origin 策略、浏览器沙箱或出站网络限制。若源站可被外部直连，仍可能绕过镜像路径。

## 验证与复现

```bash
npm run check && npm test
node tools/verify-package.cjs

docker build -t dom-mirror:local .
IMAGE=dom-mirror:local bash tools/verify-docker-session-identity.sh
```

夹具会启动自己的源站与宿主，执行真实 UI 输入及提交，再通过 WS 请求尝试恢复；不接触任何已有业务。容器 `--network none`、无宿主端口、3 GiB / 2 CPU，240 秒上限，结束后删除。原始记录默认位于 `artifacts/session-identity/`，测试报告不包含真实凭据或恢复 token。

本地原始证据根目录为 `/home/Kei/dom-mirror-validation/20261026/session-identity/`。机器可读摘要见 [session-identity-summary.json](session-identity-summary.json)，记录源码、脚本摘要、镜像及观察。使用缓存中版本不变的依赖运行时复制当前代码，`npm ls --omit=dev` 通过，不代表标准 Dockerfile 的全新在线依赖安装已完成。

本轮 22 项 Node 测试通过，覆盖可信身份读取、跨用户/租户恢复、异常/空值/Promise 拒绝，以及匿名模式兼容等。真实浏览器对照覆盖 DOM/frame；默认匿名配置的 Vikunja 草稿/路由恢复、已提交但未显示确认、同账号隔离、过期及手动重建另行回归通过。实际 tarball 安装检查、默认及 png/4ms 插桩编译均通过；最新镜像的数据边界默认/属性剔除四组检查也通过。CI 已配置身份边界检查和证据上传；本记录描述本地验收，远端 CI 结果以对应提交的 GitHub Actions 记录为准。

## 对“防渗透”的结论

本轮证明的是一个明确的恢复归属约束，不是通用攻击拦截。源站越权、注入、业务滥用、源站直连、浏览器网络访问与运行隔离仍需各自的控制和对抗验证。下一步优先明确宿主的连接撤销与允许的源站/导航/资源访问策略，保持依赖包与宿主职责清晰。
