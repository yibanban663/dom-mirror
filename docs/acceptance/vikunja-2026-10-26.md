## 验证中修复的问题

1. **首次滚动点击丢失**：浏览器的 scroll 事件可能晚于 pointerdown，上行按压到达时服务端仍在旧滚动位置。DOM 在按下前即时上报页面和目标祖先容器位置，服务端串行完成滚动再派发按压。
2. **Vue 路径漂移**：注释、空文本、相邻文本在 DOM 克隆与 HTML 重解析后会改变 childNodes 编号。实际曾出现源站用户名路径 `2/5/1/1/0/3/0/0/2/1`、镜像路径 `2/2/1/1/0/2/0/0/1/0`，源站用户名/密码均保持空值。0.9.0 改为双方一致的元素 children 索引，快照/补丁共用；旧路径不能混用。
3. **下拉框显示默认项**：API 已保存 priority=2，但 DOM 下拉框显示 Unset。序列化时同步 option 的运行时 selected 状态，并增加首快照、增量补丁和业务 UI 断言。

曾将“仅删除注释”作为中间实现，但空文本与文本合并问题仍存在，未作为最终修复。最终元素路径回归包括注释、脚本、空文本、相邻文本、页面/内层滚动和 select 状态。

自动化修正与产品修复分开：隔离容器显式清空继承代理；测试按镜像重写后的 `/m/projects/...` 识别链接；等待异步控件就绪。没有为业务操作增加失败后重试，也没有通过 API 替代被测任务写操作。

## 重现

```bash
docker build -t dom-mirror:local .
IMAGE=dom-mirror:local bash tools/verify-docker-scroll.sh
IMAGE=dom-mirror:local bash tools/verify-docker-vikunja.sh
```

输出默认在 `artifacts/scroll/` 与 `artifacts/vikunja/`，可设置 `EVIDENCE_DIR`。失败返回非零；清理通过 shell EXIT trap 执行。CI 自动运行滚动/路径/选择状态回归和 Vikunja 三通道业务回归，并分别上传结果、截图与日志。
