# 数据下发边界验收（2026-10-26）

本轮针对 0.11.0 本地工作树，只测试本地、无外网、无宿主端口的合成源站。结论是**默认修复隐藏 input 值下发，并提供显式属性剔除接口；尚未实现通用数据防泄漏或完整浏览器安全隔离**。

机器可读结果见 [data-boundary-summary.json](data-boundary-summary.json)，其中保留应用源码 SHA-256、fixture/脚本摘要、镜像标识、逐阶段观察与独立源站事件。未使用真实凭据、客户记录或业务系统；正常会话的恢复 token 不写入证据。

## 测试口径

- 先用独立浏览器上下文直连源站，证明可见、隐藏、密码、JS 变量、Cookie 和 Local Storage 的合成标记实际存在，真实点击能改变源站状态。
- DOM、frame 分别测试初始快照、改变 html/body 元数据后的更新，以及不改变文档根属性的独立增量补丁。最后一个阶段必须在 `dom-patches` 中找到对应可见标记，不能只靠全量快照通过。
- 检查 WS 文本和客户端序列化 Shadow DOM，另检查客户端 Cookie/Storage/全局变量及资源代理响应。
- 基线先观察暴露；同一合成页在修复后分别使用默认配置、`redactAttributes: ['data-private']`。每种配置都覆盖 DOM/frame，即四组、各三个阶段。
- 将修复后的强制条件用于旧代码，须因 `hidden input wire value` 失败；本轮该负对照确实失败，避免把检测不到标记误算为防护成功。
- 源站通过独立 POST 事件确认镜像操作已执行，且隐藏 input 的源站原值未被修改；普通输入回显和依赖未剔除 `data-theme` 的 CSS 也必须正常。

检索针对固定 ASCII 字面标记。未做 OCR、任意编码变换、全部 HTML/CSS 载体枚举、攻击面模糊测试或一般 sanitizer 安全审计。未开启字体混淆，不能将未命中字面标记等同于不存在可恢复的数据。

## 观察与修复

下表“下发”指在测试的 WS 文本或客户端 DOM 中发现相应标记，不等同于屏幕可见。DOM/frame 结论一致。

| 载体 | 修复前 | 修复后默认 | 显式剔除 `data-private` |
|---|---|---|---|
| 可见文本、普通输入值 | 下发 | 下发，保留交互 | 下发，保留交互 |
| 隐藏 input 的 `value` | 快照和独立增量补丁均下发 | 均不下发 | 均不下发 |
| 元素 `data-private` | 下发 | 下发 | 不下发 |
| html/body 的 `data-private` 元数据 | WS 中下发 | WS 中下发 | 不下发 |
| `display:none` 文本 | 下发 | 下发 | 下发 |
| 内联 CSS 自定义属性值 | 下发 | 下发 | 下发 |
| 未使用 CSS 规则中的字符串、字体 URL | 下发 | 下发 | 下发 |
| 图片 URL 的 query 标记 | 下发 | 下发 | 下发 |
| 密码 value、脚本标记、template/noscript/注释 | 本夹具未检出 | 本夹具未检出 | 本夹具未检出 |
| JS 运行时变量、Cookie、Local Storage 标记 | 本夹具未检出 | 本夹具未检出 | 本夹具未检出 |

html/body 元数据可能含重名属性：本夹具中 body 标记在 WS 存在，但客户端解析后未保留；这仍是下发，不能因为界面 DOM 中找不到而当作安全。独立补丁阶段不更改根属性，因此该阶段没有新的根属性标记，不能将其误算为根属性剔除成功；判断依据是初始及根属性更新阶段。

实现保持节点及路径不变，只清理镜像副本。隐藏 input 与密码、文件输入统一剔除 `value`，源站原值保留。`redactAttributes` 精确匹配属性名、忽略大小写，作用于镜像克隆以及 html/body 元数据；未配置的 `data-*` 保留。它不会删除元素、识别任意敏感文字，或擦除源站截图中的像素。配置会影响 CSS/资源依赖时需宿主逐站回归。

## 资源代理

每种配置、每个通道都实际请求九条路径：

| 响应/路径 | 观察 |
|---|---|
| PNG，附加尾随合成标记 | 200，标记随资源响应返回 |
| CSS，带未使用规则与字体 URL | 200，完整内容可获取 |
| `.png` 路径、`application/octet-stream` 内容 | 200，合成标记可获取 |
| `.json` 路径 | 403 |
| `.png` 路径、JSON 响应 | 403 |
| `.png` 路径、HTML 响应 | 403 |
| `.png` 路径、302 重定向 | 403，不跟随 |
| SVG，`image/svg+xml` | 403，目前类型过滤包含 XML，也会影响合法 SVG |
| 指向其他 origin 的路径 | 403 |

这证明当前代理能拒绝部分非静态路径和响应类型，**不会证明通过的资源只含展示数据**。允许的图片、CSS 或其他静态响应仍可携带额外数据；路径和 Content-Type 都不是敏感信息识别。属性剔除也不会清理资源正文。

首轮探索曾错误预期 SVG 能通过，实际被 XML 类型过滤拒绝，因此该失败轮次未作为完整验收。修正测试预期并加入真实 PNG 后，三阶段基线和修复后的所有组通过；记录中保留失败日志，没有放宽 JSON、HTML、重定向或异源的拒绝条件。

## 验证与复现

```bash
npm run check
npm test
node tools/verify-package.cjs

docker build -t dom-mirror:local .
IMAGE=dom-mirror:local bash tools/verify-docker-data-boundary.sh
```

默认输出 `artifacts/data-boundary/{default,redacted}/`。脚本对两个配置分别启动一次性容器，容器内完成直连、DOM/frame 验证及清理。每个容器最多运行 180 秒、3 GiB、2 CPU，`--network none`，无宿主端口。

本轮运行复用了本地缓存中版本不变的 Puppeteer/ws/sharp 依赖，复制当前应用代码后用 `npm ls --omit=dev` 校验，未依赖全新在线安装；不作为标准 Dockerfile 全新构建已完成的证据。源码与镜像标识见 JSON。原始证据在操作者本地 `/home/Kei/dom-mirror-validation/20261026/data-boundary/`。

本地校验：19 项 Node 测试通过；性能插桩默认及 png/4ms 编译锚点检查通过。修复镜像同时通过 Demo 搜索 `138`、月租 `299` 报价 `￥6,458.40` 与 frame 切换；三种滚动首次点击回归通过；Vikunja 直连、DOM/frame 的登录、创建、优先级和完成流程及独立持久化断言通过。实际 tarball 安装到独立宿主的检查也已通过。

CI 已配置此边界检查及证据上传；本记录描述本地验收，远端 CI 结果以对应提交的 GitHub Actions 记录为准。未重跑短时恢复全套，未做宿主用户越权、恶意页面执行、浏览器逃逸、完整网络访问策略、多并发容量或生产环境验收。
